# Security database

Users, permissions and (later) API keys are stored in a SQLite database that is **separate from the package database**. The rationale is recorded in the authentication architecture decision ([ADR 0002](../adr/0002-authentication-architecture.md)): the inherited package database keeps four provider-specific migration trees, and the security data must not depend on them or on which provider hosts the packages.

## Location

`Security:Database:ConnectionString` (default `Data Source=auth.db`, see the [configuration reference](../user/configuration.md)). When the server creates the file it also creates the parent directory. On Unix the directory is created with mode `0700` and the file with mode `0600`: credentials must not be world-readable. Existing files and directories are never changed.

The database must be backed up together with the package data. It uses write-ahead logging: copy it only while the server is stopped, or with SQLite's online backup (`.backup`).

## Startup behaviour

- The server applies pending migrations **before** it accepts requests, whatever the inherited `RunMigrationsAtStartup` setting says. If the database cannot be created or migrated, the host fails to start with a non-zero exit code and a message that names the path, never the connection string.
- Every connection sets a busy timeout (the connection string's `Default Timeout`, 30 seconds by default) and `journal_mode = WAL`, so the server and a concurrent command-line process do not fail with `SQLITE_BUSY` under normal use. A writer waits for another writer; readers never block writers.
- `AuthDbContext` does not implement the inherited `IContext` and is never registered as one, so the inherited migration runner and health checks never touch it.

## Data model

Table `Users`:

| Column | Type | Notes |
| --- | --- | --- |
| `Id` | `TEXT` (GUID) | generated by the application |
| `UserName` | `TEXT`, max 64 | as entered |
| `NormalizedUserName` | `TEXT`, max 64 | upper-invariant form, **unique index** |
| `PasswordHash` | `TEXT` | salted hash, never a plain-text password |
| `IsActive` | `INTEGER` | 0 or 1 |
| `Permissions` | `INTEGER` | `Permission` flags: `Read = 1`, `Publish = 2`, `Admin = 4`; values never change |
| `CreatedAt`, `UpdatedAt`, `PasswordChangedAt` | `TEXT` | UTC `DateTime`; SQLite cannot order `DateTimeOffset` values |
| `ConcurrencyStamp` | `TEXT` | concurrency token, regenerated on every update |

The migrations history table is `__AuthMigrationsHistory`. There are no foreign keys to the package database.

## Migrations

Migrations live in `src/ElPaqueto.Security/Data/Migrations/` and are generated code (excluded from the strict style checks). To add one:

```bash
dotnet ef migrations add <Name> --project src/ElPaqueto.Security --output-dir Data/Migrations
```

The command uses a design-time factory and does not build or start the host. Commit the generated files, including the model snapshot.
